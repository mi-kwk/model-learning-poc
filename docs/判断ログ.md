### AI が決めた細かい設計（利用者が見直してよい点）

| 決めたこと | 理由 |
| --- | --- |
| 作業領域 600×600、1 コマ 6 ピクセル、箱 32、置き場 80、自動実行は 400 手で打ち切り | 人がマウスで無理なく運べて、1 回が数秒で終わる大きさ |
| 座標は -1〜1 に正規化 | 入力の大きさをそろえて学習を安定させるため |
| 手本中は、青い丸（記録されるカーソル）が実際のマウスを 1 コマ 1 歩ずつ追いかける | 記録する行動（8 方向・一定の歩幅）と、画面で実際に起きた変化を一致させるため |
| マウスが止まっているコマは記録しない | 10 クラスに「何もしない」がないため |
| 学習に使うのは「成功」かつ「除外なし」の手本だけ。失敗の手本は記録として残す | 模倣学習は「真似したい行動」を学ぶので、失敗の行動は真似させない |
| 学習用と検証用は「手本の回」単位で 8:2 に分ける | コマ単位で分けると、ほぼ同じ隣のコマが両方に入り、検証が甘くなるため |
| 「つかむ」「離す」の誤差を重くする（出現回数の逆数の平方根） | 1 回の手本に 1 コマずつしかない少数派の行動が無視されないように |
| 学習は 400 エポック（Adam、学習率 0.001、バッチ 128） | 合成手本で試したところ、150 エポックでは成功率 45%、400 エポックでは 80% だったため（下の検証記録） |
| 評価用の配置は乱数シード 9,000,000 番台、手本は 0〜999,999 | 評価が必ず「学習に使っていない配置」になるように |
| ~~自動実行は確率がいちばん高い行動を選ぶ~~ → 確率に従ってくじ引きで選ぶ（評価では乱数の種を 0 に固定） | 最初は再現性を優先して最大を選んでいた。利用者の手本で失敗を分析した結果、同じ行動の繰り返しで止まっていたため変更（下の「失敗の分析と修正」） |
| 検証誤差が最小のエポックに戻す仕組み（アーリーストッピング）は、作ったが既定では使わない | 試したところ成功率が下がったため。`train.py --early-stop` で比較用に使える |

### 失敗の分析と修正（2026-11-08、利用者の手本 58 回を使用）

1. **AI の最初の診断（外れた）**：学習誤差 0.58 に対して検証誤差が 4.6 まで上がっていたため、「過学習が成功率 10% の原因」と説明し、アーリーストッピングを提案した。
2. **試した結果**：手本 50 回で、学習の乱数を変えて 3 回試した。成功率の平均は 7% → 0% に下がった（合成手本でも 63% → 25%）。検証誤差が最小のエポック（4〜15）では、まだ学習が足りなかった。
3. **失敗の観察**：失敗 18 回はすべて「つかむ前」だった。9 回は箱の手前で「つかむ」を繰り返し、9 回は 2 方向を行ったり来たりしていた。
4. **仮説と検証**：確率が最大の行動を必ず選ぶため、同じ状態から抜け出せないと考えた。くじ引きで選ぶ方式を試したところ、3 回平均で 7% → 37%、合成手本で 63% → 100% になった。
5. **ほかに試したこと**：「つかむ」「離す」の誤差を重くする設定をやめると、くじ引きでも 37% → 22% に下がったので、重くする設定は残した。

教訓：検証誤差だけを見て直す方向を決めると外れることがある。実際に動かして失敗の様子を見てから原因を決める。

### 段階 2 で AI が生成・決めたこと（2026-11-08）

生成したコード：`poc/render.py`（描画の共通化）、`poc/vision.py`（見るモデル・画像データ作成・学習）、`train_vision.py`、`annotate.py`、`app.py` の `4` キーのモード、`evaluate.py --vision`、`poc/runner.py` の「状態の知り方（observe）」の差し替え口。

| 決めたこと | 理由 |
| --- | --- |
| 見るモデルの出力を、段階 1 の入力と同じ 7 つの数値にした | 動くモデルを作り直さずに使うため |
| 画像は 600×600 の画面を 128×128 に縮めて使う | CPU で数分で学習できる大きさ。箱は約 7 ピクセルになる |
| つかまれている箱を黄色で描くように画面を変えた（段階 1 の画面も同じ） | 画像だけでは、カーソルが箱の上にいるだけなのか、つかんでいるのか区別できないため |
| 正解の位置はプログラムから自動で付ける（自動アノテーション）。人の印は確認用 | 8,000 枚に人が印を付けるのは現実的でないため |
| 位置はヒートマップの重心で出す。画像は白黒を反転して入れる | 最初の作り（全結合で直接数値にする）が学習しなかったため |
| 学習用の画像に、カーソルが画面の端にいる場面を足した | 自動実行中に端で大きく見間違えていたため |
| 畳み込み層にバッチ正規化を入れた | 入れない版は、初期値しだいでカーソルを学習できなかったため |
| 画面の角の見間違いは直していない | 成功率への影響が小さく、時間を優先したため（段階2メモの 6） |

詳しい経緯と結果は [段階2メモ.md](段階2メモ.md) にまとめました。

### AI が行った動作確認（人の手本ではない）

`tools/make_synthetic_demos.py` で、機械の手本役（15% の確率で隣の方向にぶれる）に 50 回分の手本を作らせて確認しました。成果として示すときは、この数字ではなく自分で記録した手本の結果を使ってください。

- 手本 5 / 20 / 50 回 → 成功率 0% / 10% / 80%、ランダム行動は 0%（400 エポック）
- 150 エポックでは手本 50 回で 45%。失敗のほとんどは「箱の少し手前で『つかむ』を選ぶ → 何も起きない → 同じ状態なので同じ行動を繰り返して止まる」だった
- クラス重みをなくすと、150・400 エポックとも 70%
- 画面の動作（手本の記録・除外・再生・学習・自動実行・評価・ランダム）は、画面を表示しない設定で、マウス操作を模擬して確認した。**実際のマウスで手本を記録する操作感は、利用者による確認が必要**
