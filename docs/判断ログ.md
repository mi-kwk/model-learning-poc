### AI が決めた細かい設計（利用者が見直してよい点）

| 決めたこと | 理由 |
| --- | --- |
| 作業領域 600×600、1 コマ 6 ピクセル、箱 32、置き場 80、自動実行は 400 手で打ち切り | 人がマウスで無理なく運べて、1 回が数秒で終わる大きさ |
| 座標は -1〜1 に正規化 | 入力の大きさをそろえて学習を安定させるため |
| 手本中は、青い丸（記録されるカーソル）が実際のマウスを 1 コマ 1 歩ずつ追いかける | 記録する行動（8 方向・一定の歩幅）と、画面で実際に起きた変化を一致させるため |
| マウスが止まっているコマは記録しない | 10 クラスに「何もしない」がないため |
| 学習に使うのは「成功」かつ「除外なし」の手本だけ。失敗の手本は記録として残す | 模倣学習は「真似したい行動」を学ぶので、失敗の行動は真似させない |
| 学習用と検証用は「手本の回」単位で 8:2 に分ける | コマ単位で分けると、ほぼ同じ隣のコマが両方に入り、検証が甘くなるため |
| 「つかむ」「離す」の誤差を重くする（出現回数の逆数の平方根） | 1 回の手本に 1 コマずつしかない少数派の行動が無視されないように |
| 学習は 400 エポック（Adam、学習率 0.001、バッチ 128） | 合成手本で試したところ、150 エポックでは成功率 45%、400 エポックでは 80% だったため（下の検証記録） |
| 評価用の配置は乱数シード 9,000,000 番台、手本は 0〜999,999 | 評価が必ず「学習に使っていない配置」になるように |
| 自動実行は確率がいちばん高い行動を選ぶ（毎回同じ結果になる） | 評価の再現性のため。同じ状態で動けなくなる弱点がそのまま見える |

### AI が行った動作確認（人の手本ではない）

`tools/make_synthetic_demos.py` で、機械の手本役（15% の確率で隣の方向にぶれる）に 50 回分の手本を作らせて確認しました。成果として示すときは、この数字ではなく自分で記録した手本の結果を使ってください。

- 手本 5 / 20 / 50 回 → 成功率 0% / 10% / 80%、ランダム行動は 0%（400 エポック）
- 150 エポックでは手本 50 回で 45%。失敗のほとんどは「箱の少し手前で『つかむ』を選ぶ → 何も起きない → 同じ状態なので同じ行動を繰り返して止まる」だった
- クラス重みをなくすと、150・400 エポックとも 70%
- 画面の動作（手本の記録・除外・再生・学習・自動実行・評価・ランダム）は、画面を表示しない設定で、マウス操作を模擬して確認した。**実際のマウスで手本を記録する操作感は、利用者による確認が必要**
